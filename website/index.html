Supply-chain security for AI coding agents

Your agent wants to install it.
Warden checks it first.

Warden stops AI coding agents and dependency updates from installing fake, look-alike, or tampered npm packages before they ever run.

Install from source Node 22.12+ · no AI model · no account
git clone https://github.com/hamza-paracha/warden.git && cd warden && npm ci && npm run build && npm install -g .

Then run warden agent-setup claude devin in your project.

Source-only for now. The commands on this page are on the main branch and ship in the next npm release. Until then, npm install -g @devdonzo/warden installs an older version without them.

Why it matters

Most security tools only catch attacks that are already known.

In 2025, hijacked versions of popular packages and a self-spreading worm were installed for hours before anyone flagged them. Warden compares each new version with the one before it and flags anything risky it adds, so normal updates stay quiet.

What you can do with it

Check packages before, during, and after a change.

Source-only until the next npm release.

  1. 01

    Before installing

    Check any package before it touches your machine.

    warden inspect express
  2. 02

    Pull requests

    Check every package a pull request adds, without running its code.

    warden review . --base main
  3. 03

    Security fixes

    Confirm a fix removed the vulnerability and the tests still pass.

    warden verify
  4. 04

    Proof

    Sign the results so reviewers can tell nothing was changed.

    warden attest

Works with your AI agent

One command protects every install your agent makes.

Warden checks installs before they run and tells the agent why it blocked one, so it can pick a safe package instead. Agents can also ask Warden directly before they choose a dependency.

warden agent-setup claude devin codex
